# Mode B 評估協定（B1）：一把固定的尺

> 2026-09-14。規格 §6 把評估協定寫成四條不可退化的規則。
> 這一份把那四條變成**程式會執行的東西**：`scripts/closeup_eval.py`。
> 前置是 [`CLOSEUP_SPLIT_GROUPS.md`](CLOSEUP_SPLIT_GROUPS.md) 的切分群組。

---

## 0. 三個結論

1. **洩漏值 0.204。** 同一組 test（語料官方的 161 張）、同一個 1-NN、同一組描述子，
   只差訓練池裡有沒有同 `split_group` 的照片——平均逐類 recall 從 0.605 掉到 0.401。
   這不是推論，是配對實驗量出來的。
2. **1-NN 是地板不是基線。** 群感知 5 折下抄最近鄰居的逐類 recall 是 0.25–0.64。
   任何模型報出來的數字若沒有明顯高過這一排，它學到的東西不比「這張長得像那張」多。
3. **誤報歸因補起來了，健康照仍然沒有。** 正常結構普查已補到取像合格的 839 張**全覆蓋**，
   「未普查」那一格從 523 張降到 **0**，痕跡子集從「每類都不足 30、全部不報」變成 231 張報得出數字。
   剩下的缺口是**健康照 0 張**——§6 第 4 條要的「誤報在乾淨表面上」仍然量不到，那要另外拍。

## 1. 四條規則的執行方式

| §6 | 規則 | 程式怎麼執行 |
|---|---|---|
| 1 | 按葉片切不按照片切 | 切分只能來自 `closeup_blade_groups_wtb.json`；預測檔要**宣告**用哪一種，宣告與 `--split` 不符**拒跑**。允許跑 `official`（示範洩漏用），但報告會蓋上洩漏印記並列出被拆開的群 |
| 2 | 主指標是逐類 recall | 逐類表是第 1 節；整體 accuracy 只出現在最後一節、標明「附註，不得當標題」 |
| 3 | 每類少於 30 張不報 P/R/F1 | 數字位置印「不報」，連小數點都不出現（有測試檢查那一列） |
| 4 | 誤報分開報 | 三格：有正常結構的影像上／普查過但沒有的／**未普查**。健康照 0 張時印「量不到」而不是 0。普查已補到評估域全覆蓋，第三格現為 0（§3.5） |

評估域預設是**取像合格的 839 張**（`--domain intake_P`）：Mode B 的輸入定義是 §1.2 合格的近身照，
在整機照上評估沒有意義，而且那些影像也不在正常結構普查的覆蓋內。`--domain all` 保留作對照。

另外兩件：**低光照子集**單獨報（§6 補充，定義是可重現的量——V 通道均值低於語料自身第 20 百分位 = 134.3/255，
不是人的印象）；**機制類彙總只在對照明確時才做**——分類表顯示六類裡只有
`crack`／`surface_injure`／`thunderstrike` 對得上單一機制類，其餘三類跨機制類，硬彙總會產生
一個不能跟基線論文比的數字。

## 2. 洩漏值多少分（配對實驗）

同一組 test、同一個模型，只變一個變數：訓練池裡有沒有同群照片。
161 張 test 裡 **102 張**在官方 train 裡有同群照片。

| 類別 | 真值張數 | 有同群可抄 | 扣掉同群 | 差 |
|---|---|---|---|---|
| `surface_injure` | 41 | 0.659 | 0.390 | **+0.268** |
| `hide_craze` | 40 | 0.700 | 0.675 | **+0.025** |
| `corrosion` | 36 | 0.444 | 0.306 | **+0.139** |
| `craze` | 34 | 0.618 | 0.235 | **+0.382** |
| `crack` | 23 | 不報 | 不報 | — |
| `thunderstrike` | 16 | 不報 | 不報 | — |

**平均逐類 recall 差 +0.204。**

誠實的邊界：1-NN 對記憶最敏感，所以這是**抄鄰居這種行為**能拿到的虛高幅度，
不是任何特定模型會漲幾分的預測值。它證明的是「按照片切會獎勵記憶」，這一點對任何會記憶的模型都成立。

## 3. 1-NN 在群感知 5 折下的成績（地板）

評估域是**取像合格的 839 張**（Mode B 的輸入定義 §1.2）。`crack` 在這個域裡真值 0 張——
分類表早就寫了這一類「在 Mode B 的輸入定義下不存在」，這裡是同一件事的執行面。
它仍有 117 個誤報：模型從整機照鄰居抄過來，這正是**評估域要對**的理由。

| 類別 | 真值張數 | recall | precision | F1 |
|---|---|---|---|---|
| `surface_injure` | 272 | 0.426 | 0.504 | 0.462 |
| `hide_craze` | 245 | 0.506 | 0.444 | 0.473 |
| `craze` | 206 | 0.262 | 0.380 | 0.310 |
| `corrosion` | 191 | 0.277 | 0.342 | 0.306 |
| `thunderstrike` | 89 | 0.247 | 0.361 | 0.293 |
| `crack` | 0 | 不報 | 不報 | 不報 |

逐折 recall 的範圍（單一折走運會在這裡露出來）：

| 類別 | 最低 | 最高 |
|---|---|---|
| `corrosion` | 0.222 | 0.359 |
| `craze` | 0.178 | 0.348 |
| `hide_craze` | 0.400 | 0.696 |
| `surface_injure` | 0.375 | 0.500 |
| `thunderstrike` | 0.056 | 0.500 |

`thunderstrike` 的逐折差距是個提醒：89 張的類別在 5 折下每折只有 18 張，單折數字不可讀。

## 3.5 誤報歸因與痕跡子集（普查補滿之後）

**正常結構普查已補到取像合格的 839 張全覆蓋**（2026-09-14，見
[`CLOSEUP_HEALTHY_SET.md`](CLOSEUP_HEALTHY_SET.md) §3）。第一版 192 張抽樣時，
656 張有誤報的影像裡有 **523 張落在「未普查」**，§6 第 4 條形同虛設。現在：

| 誤報落在哪裡 | 張數 |
|---|---|
| 有正常結構的影像上 | 130 |
| 普查過、沒有正常結構的影像上 | 423 |
| **未普查** | **0** |

痕跡子集同樣從「全部不報」變成報得出來（68 張 → 231 張）：

| 子集 | 張數 | `corrosion` | `crack` | `craze` | `hide_craze` | `surface_injure` | `thunderstrike` |
|---|---|---|---|---|---|---|---|
| yes | 231 | 0.118 | 不報(0) | 0.314 | 0.571 | 0.312 | 不報(22) |
| no | 608 | 0.336 | 不報(0) | 0.235 | 0.480 | 0.472 | 0.239 |

1-NN 在帶痕跡的影像上 `corrosion` recall 0.118、無痕跡 0.336，`surface_injure` 0.312 vs 0.472——
**差距是真的存在的**，只是在補滿普查之前量不到。這不代表痕跡「造成」差異
（帶痕跡的影像也可能本來就比較難），但 §12 建議的「痕跡子集單獨報數字」現在有執行條件了。

## 4. 預測檔格式

```json
{
 "model": "你的模型名稱／版本",
 "split": "folds",
 "predictions": {"0": ["craze"], "1": [], "2": ["surface_injure", "corrosion"]}
}
```

鍵是影像編號（字串 0–1064），值是預測到的類別清單（可為空）。`split` 必填。
沒有預測的影像一律當成「什麼都沒預測」計入 FN，報告會列出涵蓋率。
打錯的類別名或影像編號**拒跑**而不是默默計分。

## 5. 這份語料還有什麼做不到

- **健康照 0 張**：誤報率的分母不存在。要另外拍（分類表 §2 的 12 項是拍攝清單）。
  這是普查補滿之後**唯一沒解的那一條**。
- **普查是單一標註者、在 460 px 印樣上做的**：`L`（避雷接點）與 `v`（VG／鋸齒尾緣）
  在 839 張裡全 0，但那是「印樣上沒看到」不是「不存在」；`s`（接縫）兩批判準不一致，
  數字不可用（標記檔的 `consistency_caveat` 寫了）。
- **域外的 226 張仍未普查**：整機照不是 Mode B 的輸入，`--domain all` 下「未普查」那一格會回來。
- **沒有尺度**：用這份語料訓出來的模型不得輸出 IEA Level（§9.4）。
- **上限是 94.0%**：兩位標註者的類別一致率（kappa 0.897）。超過它的分數是在報雜訊。

## 6. 重現

```bash
cd blade_prototype
python scripts/closeup_eval.py template                                   # 預測檔格式
python scripts/closeup_eval.py nn-baseline <語料根目錄> --split folds --out preds.json
python scripts/closeup_eval.py eval --predictions preds.json --markdown report.md
python scripts/closeup_eval.py leakage-demo <語料根目錄>                  # §2 的配對實驗
pytest tests/test_closeup_eval.py                                         # 四條規則的反向測試
```

真值 [`data/closeup_truth_wtb.json`](data/closeup_truth_wtb.json)（兩位標註者的聯集）與
子集旗標 [`data/closeup_subsets_wtb.json`](data/closeup_subsets_wtb.json) 已進版控，
所以評估**不需要語料本體**也跑得動；只有 `truth`／`subsets`／`nn-baseline`／`leakage-demo` 要語料。
