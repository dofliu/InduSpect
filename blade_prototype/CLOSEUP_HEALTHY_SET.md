# Mode B 健康照與正常結構標註：第一版（B0 後續）

> 2026-09-13。接續 [`CLOSEUP_BASELINE_REPORT.md`](CLOSEUP_BASELINE_REPORT.md) §5.2 的結論：
> 唯一可商用的語料 1065 張**一張健康照都沒有、一個正常結構標註都沒有**，
> 所以規格 §6 第 4 條（誤報分開報「在正常結構上」與「在乾淨表面上」）執行不了。
> 這一份做的是**讓那件事變得可能**的部分。
>
> **全部產出都是單一標註者（本次作業的模型）的第一版，沒有人複核過。**
> 它們的價值是「有起點、可追溯、可被推翻」，不是真值。任何一筆要進訓練集或測試集之前，
> 都要有人看過並簽名（分類表判定順序第 7 條：`healthy` 是看過且確認乾淨，不是沒標到）。

## 0. 四個結論

1. **取像判定做完全部 1065 張：839 張合格（79%）。** `crack` 類 **0/177** 通過——174 張是整機照。
   B0 報告用 32 張抽樣說的事，現在是全語料的數字。
2. **與結構類缺陷最易混淆的三種正常結構在這份語料裡不存在。** 取像合格的 **839 張全部普查**過
   （2026-09-14 補完；第一版是 192 張抽樣），避雷接點、VG 板、排水孔**一張都沒出現**。
   出現的是紅色葉尖塗裝（14%）、文字標記（7%）、比例尺（4%）、修補痕（3%）。
   **§6 第 4 條要的「含易誤判正常結構的健康照」，這份語料補不齊，要另外拍。**
3. **標註與前處理痕跡比任何正常結構都多。** 灰色矩形塗抹 20%、時間戳燒錄 12%、人手工具入鏡 8%——
   合計 **35% 的合格影像**帶著「這裡有人在標缺陷」的線索。模型很可能學到「灰色矩形附近有缺陷」。
   **這是比缺健康照更迫切的洩漏風險**，訓練前要先處理。
4. **從框外區域挖出 1,842 格健康候選，第一遍逐格看過。** 6,880 格候選中 1,842 格看起來像葉片表面；
   2026-09-14 把這 1,842 格**逐格**看過一遍（§7）：**788 格（42.8%）是葉片表面**、648 格（35.2%）
   是葉片與背景的邊界、274 格不是葉片、132 格判不了。原本「約 64%」是 64 格抽樣的推估，
   逐格看完後低了 21 個百分點——**抽樣把邊界格算成了葉片表面**。
   **第一遍的標註者是模型不是人**，全部 `unreviewed`；篩的工具做好了（§6），決策檔仍是 0 筆。

### 3.2 沒出現的正常結構（全普查後仍然是 0）

B0 報告 §5.4 引的基線論文裡，YOLOv8n 的 11 張健康照誤報就落在「製造接縫與結構標記」上——
**而這份語料連讓那種誤報發生的機會都沒有**。用它訓出來的模型，第一次看到避雷接點會發生什麼事，
沒有任何資料可以回答。

### 3.3 標註與前處理痕跡

| 痕跡 | 張數 | 占比 |
|---|---|---|
| 時間戳或文字燒錄在影像上 | 109 | 13.0% |
| 灰色矩形塗抹（發布前的去識別化／修補） | 98 | 11.7% |
| 人、手、工具入鏡 | 58 | 6.9% |
| **任一種** | **231** | **27.5%** |

三件事：

- **痕跡仍比正常結構多**：含正常結構的 221 張、

  那些才是誤報歸因裡「乾淨表面」的分母。

  「畫面有時間戳就有缺陷」，在沒有這些痕跡的真實照片上崩掉。補完普查之後這件事**量得到了**：

### 3.4 兩批之間判準不一致的兩個碼

`s`（接縫／分模線）第一批 192 張標了 5 張（2.6%）、第二批 647 張標了 **0** 張；`e`（LEP 邊緣階差）
全語料只有 1 張。差的不是語料是判準——第二批把「葉片邊緣線」與「表面上的分模線」分開看。
**這兩碼只能當「看到過」，不能當盛行率**，標記檔的 `consistency_caveat` 寫了同一句話，有測試守著。

這件事本身是個量測：**同一個標註者、同一個版面、隔一段時間，影像級存在標記的可重複性有限。**
要當真值用的標記，需要第二個人獨立複核。

| 第一遍的碼 | 格數 | 占比 |
|---|---|---|
| `b` 葉片表面 | **788** | 42.8% |
| `e` 葉片與背景的邊界 | 648 | 35.2% |
| `n` 不是葉片（天空／地景／器材／文字） | 274 | 14.9% |

**含葉片的格子 78.0%，但純表面只有 42.8%**——抽樣時的「64%」把大量邊界格算成了葉片表面。
這件事很重要：邊界格的對比來自天空不是漆面，混進健康記憶庫會讓模型把「有邊」學成正常。
殘餘的 `n` 主要是灰藍色、有一點紋理的天空（紋理下限擋不掉），少數是地景與工具。

兩條不可退化的約定：

1. **全部 `unreviewed`。** 兩位標註者都沒框 ≠ 確認乾淨——他們只框自己要框的。升成 `healthy` 要人看過。
2. **`bg_guess` 不是標籤，是排序。** 它只是讓人先看最可能是葉片的格子，不能拿它當 healthy 的依據。

另一個要記的事：這些候選**與缺陷影像同源**（同一支葉片、同一次飛行）。依 §6 第 1 條「按葉片切」，
它們必須跟原影像分在同一側，否則健康樣本會洩漏到測試集。語料沒有葉片編號（B0 報告 §5.2）——
**這件事已經解了**（2026-09-14，[`CLOSEUP_SPLIT_GROUPS.md`](CLOSEUP_SPLIT_GROUPS.md)）：
用影像重疊連出 524 個 `split_group`，每一格候選現在都帶著來源影像的群號（manifest 的 `split_group` 欄位）。
順帶量到語料自己附的切分洩漏 63.4%，不可以用。檔名相鄰性則**完全不帶結構**——
同一次飛行的 25 張散在 69…851。

## 6. 複核工具：把第一版標記變成可簽核的東西

上面三份產出全部停在 `unreviewed`／`pending`，而在有人看過之前它們一筆都不能用。
`scripts/closeup_review_tool.py` 是那道門：

```bash
# 1. 產離線工作區（切圖 + 單檔 HTML，約 32 MB／1,866 筆）
python scripts/closeup_review_tool.py build <語料根目錄> <工作區目錄> \
       --manifest <Pass 3 的 healthy_candidates.json>
# 2. 瀏覽器開 <工作區目錄>/review.html，鍵盤 y／n／u／s 逐筆判，可中斷續做，做完「匯出決策」
# 3. 併進版控中的決策檔（這一步才會擋不合格的簽核）
python scripts/closeup_review_tool.py ingest <下載的 decisions.json> \
       --items <工作區目錄>/items.json --annotator "你的名字"
python scripts/closeup_review_tool.py status --items <工作區目錄>/items.json   # 還差多少
```

三個佇列，各自宣告「yes 是什麼意思」：

| 佇列 | 筆數 | yes 代表 | 寫進去的狀態 |
|---|---|---|---|
| `healthy` 健康候選格 | 1,842（`blade_like`，可用 `--bg` 改） | 這 256 px 是葉片表面且乾淨 | `healthy` |
| `ns_recheck` `x` 全解析度複核 | 6 | 印樣上標的陰影／反光成立 | `confirmed` |
| `boxes` 概略框複核 | 18（19 筆中 654 那筆無框） | 框的位置與類別都對 | `confirmed` |

畫面一次給兩樣東西：**被判的切圖**（原尺寸，256 px 的自動放大到 2×）與**整張的上下文**（長邊 512，
上面標出這一格的位置）。判「這格是不是葉片表面」需要上下文，判「乾不乾淨」需要原尺寸，缺一個都會判錯。

四條不可退化的約定，每一條都有反向測試（`tests/test_closeup_review_tool.py`）：

1. **升格一定要人名。** `annotator` 長得像模型（`claude*`／`gpt*`／`model*`／空的）整批拒收——
   第一版標記用的 `claude-first-pass` 不可以經由這條路變成簽核。
2. **跳過 ≠ 乾淨。** 跳過與沒看的都不寫進決策檔，維持 `unreviewed`。「兩位標註者都沒框」本來就
   不等於確認乾淨，複核工具不可以把「沒看」再變成一次「沒問題」。
3. **不得在縮圖上升格。** 每筆決策記下當下量到的顯示倍率（顯示 px ÷ 原圖 px），
   倍率 < 1.0 的 `yes` 在匯入時被擋下；否決不受限（縮圖也看得出不是葉片）。
   來由是 §5 的 654：印樣上看成硬邊陰影，全解析度看是葉片與天空的邊界。
   畫面上這條是**靠構造成立**的——切圖一律以原尺寸顯示、容器自己捲，不會被版面縮掉，
   匯入時的檢查是外部匯入與瀏覽器縮放的後備。
4. **決策綁在像素上。** `item_id` 是「佇列＋檔名＋座標」的雜湊。候選用不同 `--tile`／`--margin`
   重新產生後，對不上的決策會被 `status` 列為失效，不會被默默套到別的像素上。

決策檔 [`data/closeup_review_decisions.json`](data/closeup_review_decisions.json) 進版控，
目前 **0 筆**——沒有人簽核過任何一筆。測試守著它：裡面若出現沒有人名、或在縮圖上做的升格，會紅。

## 7. 第一遍逐格標記：1,842 格看過一遍（**不是簽核**）

§4 的「約 64% 是葉片表面」是 64 格抽樣的推估，而複核要從 1,842 格開始——沒有順序，就等於從頭翻。

**原尺寸 256 px 不縮放**）逐格看過一遍，收成版控檔
[`data/closeup_healthy_firstpass_wtb.json`](data/closeup_healthy_firstpass_wtb.json)。

格子不縮放是刻意的：縮了就看不出紋理，也就回到 654 那個錯誤（§5 的教訓）——
在印樣上看成硬邊陰影的東西，全解析度下是葉片與天空的邊界。

| 碼 | 意思 | 格數 | 占比 |
|---|---|---|---|
| `b` | 葉片表面（幾乎整格都是漆面） | **788** | 42.8% |
| `e` | 葉片與背景的邊界（含葉片但不是純表面） | 648 | 35.2% |
| `n` | 不是葉片（天空／地景／器材／文字浮水印） | 274 | 14.9% |
| `u` | 判不了（過曝／全平／模糊／被塗抹） | 132 | 7.2% |

**這一遍不是簽核**，三條不可退化（反向測試在 `tests/test_closeup_firstpass.py`）：

1. **標註者一律 `claude-first-pass`、狀態一律 `unreviewed`。** 這個名字正好落在
   `closeup_review_tool.MODEL_ANNOTATOR` 的黑名單裡——它**進不了決策檔**。
   `pack` 還會自我對帳：黑名單哪天放寬到擋不住這個名字，它就拒絕產出檔案。
2. **它只改變順序與先驗。** `closeup_review_tool.py build` 預設吃這份標記，把 `b` 排在最前面、
   `n` 排在最後，並在每格的說明上標「第一遍 b（…，未複核）」；**不寫任何決策**。
   誰有權說 healthy 沒有變。
3. **身分綁像素。** 每格的 `item_id` 與 `healthy` 佇列同一套雜湊（`sha1(queue|image|x,y,w,h)`）；
   候選用不同 `--tile/--margin` 重新產生後對不上的，`verify` 會點名而不是默默沿用。

複核的隊現在看得到進度：

```
$ python scripts/closeup_review_tool.py status --items <工作區>/items.json
決策 0 筆，簽核人 （無）
還沒看的：
  healthy: 1842
  （healthy 依第一遍先驗，未複核：b 788、e 648、n 274、u 132）
```

**這一遍改了一個數字**：可用候選從「約 1,200 格」降到 **788 格純表面**（含邊界格 1,436）。
抽樣時把邊界格算成了葉片表面——邊界格的對比來自天空不是漆面，混進健康記憶庫會讓模型把「有邊」
學成正常，正是 §0 第 4 條那種「寧可少收一筆不要收一筆錯的」情況。

## 8. 對規格與分類表的回饋

1. **§6 加一條：帶標註／前處理痕跡的影像單獨切子集報數字。** 理由見 §3.3。
2. **§6 第 4 條在這份語料上做不到，要另外拍健康照。** 拍攝清單就是分類表 §2 的 12 項，
   優先補這份語料沒有的三種：避雷接點、VG 板／鋸齒尾緣、排水孔。B0 報告 §3 已證明開放網路湊不出來。
3. **分類表 `dataset_class_map` 已更新**：`crack` 的說明改成全語料數字，並新增 `normal_structure_survey` 區塊。
4. **`scale.method = reference_object` 有實例了**：11/192 張有比例尺入鏡。B1 可以先用這些量 cm/px，
   不必等 XMP。

## 9. 誠實的邊界

- **單一標註者、未複核。** 三份標記檔與所有數字都是。§5 的 654 就是一個判錯後修正的例子——
  其他沒重看的很可能還有。
- **Pass 1 判的是取景不是內容**：`P` 只說「葉片占畫面夠大」，不說「這張能用來訓什麼」。
- **Pass 2 的解析度看不到小東西**：避雷接點在 460 px 的格子裡可能就是幾個像素。「0 張」是「印樣上沒看到」，
  全解析度普查會不會找到幾張，不確定；但即使找到，也不會多到能撐一個類別。
- **Pass 2 兩批之間的判準不一致**（§3.4）：`s` 與 `e` 兩碼的數字不可用。同一個標註者隔一段時間
  就會漂，這正是「要有人複核」的量化理由。
- **Pass 3 的候選只是候選**：1,842 格已逐格看過一遍（§7），但看的是模型。
  42.8% 這個數字是第一遍的，不是簽核後的。
- **沒有跑任何模型。**
- **複核工具做好了，但一筆都還沒複核。** 工具讓那件事可以被執行，不代表已經被執行；
  決策檔目前 0 筆。第一遍標記（§7）只改變複核的順序，不改變誰有權說 healthy。
