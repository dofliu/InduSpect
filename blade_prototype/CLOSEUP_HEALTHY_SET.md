# Mode B 健康照與正常結構標註：第一版（B0 後續）

> 2026-09-13。接續 [`CLOSEUP_BASELINE_REPORT.md`](CLOSEUP_BASELINE_REPORT.md) §5.2 的結論：
> 唯一可商用的語料 1065 張**一張健康照都沒有、一個正常結構標註都沒有**，
> 所以規格 §6 第 4 條（誤報分開報「在正常結構上」與「在乾淨表面上」）執行不了。
> 這一份做的是**讓那件事變得可能**的部分。
>
> **全部產出都是單一標註者（本次作業的模型）的第一版，沒有人複核過。**
> 它們的價值是「有起點、可追溯、可被推翻」，不是真值。任何一筆要進訓練集或測試集之前，
> 都要有人看過並簽名（分類表判定順序第 7 條：`healthy` 是看過且確認乾淨，不是沒標到）。

---

## 0. 四個結論

1. **取像判定做完全部 1065 張：839 張合格（79%）。** `crack` 類 **0/177** 通過——174 張是整機照。
   B0 報告用 32 張抽樣說的事，現在是全語料的數字。
2. **與結構類缺陷最易混淆的三種正常結構在這份語料裡不存在。** 192 張抽樣裡，避雷接點、VG 板、
   排水孔**一張都沒出現**。出現的是紅色葉尖塗裝（10%）、比例尺（6%）、文字標記（4%）、
   接縫（3%）、修補痕（2%）。**§6 第 4 條要的「含易誤判正常結構的健康照」，這份語料補不齊，要另外拍。**
3. **標註與前處理痕跡比任何正常結構都多。** 灰色矩形塗抹 20%、時間戳燒錄 12%、人手工具入鏡 8%——
   合計 **35% 的合格影像**帶著「這裡有人在標缺陷」的線索。模型很可能學到「灰色矩形附近有缺陷」。
   **這是比缺健康照更迫切的洩漏風險**，訓練前要先處理。
4. **從框外區域挖出約 1,200 格可用的健康候選。** 6,880 格候選中 1,842 格看起來像葉片表面，
   目視抽 64 格約 64% 真的是；全部 `unreviewed`，等人篩。

## 3. Pass 2：正常結構普查，192 張

從 839 張合格影像等距抽 192 張，看畫面裡**有沒有**分類表 §2 的正常結構，以及有沒有標註／前處理留下的痕跡。

### 3.1 有出現的正常結構

| 正常結構 | 張數 | 占比 | 備註 |
|---|---|---|---|
| `tip_marking`（紅色葉尖航警塗裝） | 20 | 10.4% | 最常見；白色露出處常是缺陷框所在，紅色本身不是 |
| 比例尺（鋼尺／捲尺入鏡） | 11 | 5.7% | 不是葉片結構，但正是 `scale.method = reference_object` 的實例 |
| `marking_decal`（文字、告示牌、商標） | 7 | 3.6% | 含手持檢測告示牌 |
| `shadow_and_specular` | 6 | 3.1% | |
| `mould_parting_line` / `paint_seam` | 5 | 2.6% | |
| `repair_patch` | 4 | 2.1% | 黃色玻纖修補層，中央常有新的燒蝕 |
| `lep_edge_step` | 1 | 0.5% | 只在全解析度上看得出來 |

### 3.2 沒出現的正常結構

**`lightning_receptor`、`vortex_generator` / `serrated_trailing_edge`、`drain_hole`：192 張裡 0 張。**

這三種正是與 `environmental/lightning_damage`、`structural/delamination`、`surface/surface_pitting`
最易混淆的（分類表 §2 的 `confused_with`）。B0 報告 §5.4 引的基線論文裡，YOLOv8n 的 11 張健康照誤報
就落在「製造接縫與結構標記」上——**而這份語料連讓那種誤報發生的機會都沒有**。
用它訓出來的模型，第一次看到避雷接點會發生什麼事，沒有任何資料可以回答。

### 3.3 標註與前處理痕跡

| 痕跡 | 張數 | 占比 |
|---|---|---|
| 灰色矩形塗抹（發布前的去識別化／修補） | 38 | 19.8% |
| 時間戳或文字燒錄在影像上 | 23 | 12.0% |
| 人、手、工具入鏡 | 15 | 7.8% |
| **任一種** | **68** | **35.4%** |

三件事：

- **痕跡比正常結構多。** 含分類表定義之正常結構的影像 45 張（23%），含痕跡的 68 張（35%）。
- **痕跡與缺陷同時出現**（這是缺陷語料，每張都有缺陷）。模型完全可能學到「灰色矩形附近有缺陷」
  「畫面有時間戳就有缺陷」，在沒有這些痕跡的真實照片上崩掉。
- **灰色矩形塗抹會落進健康候選。** Pass 3 第一版就是這樣：`bg_guess = blade_like` 的 64 格抽樣裡
  約四成是平塗灰塊或過曝白，補了一條紋理下限（灰階標準差 < 4 一律 `flat_or_blank`）才降下來。

**建議**：訓練前把 `a`／`t` 標記的影像單獨切一個子集報數字（同 §6 對低光照的處理），
或至少在評估時確認模型對「無痕跡照片」的 recall 沒有掉。這條應該進規格 §6。

## 4. Pass 3：健康候選挖掘

```
python scripts/closeup_healthy_candidates.py <語料根目錄> <輸出目錄>
```

| 量 | 值 |
|---|---|
| 考慮的影像 | 839（取像合格） |
| 有至少一格候選的影像 | 820 |
| 候選格總數（256 px，與兩位標註者的擴框無交集） | **6,880** |
| `flat_or_blank`（過曝白、平塗灰塊） | 2,399 |
| `blade_like`（低飽和、中亮度、有紋理） | **1,842** |
| `blade_like` 且影像無痕跡標記 | 1,588 |
| `sky_like` / `vegetation_like` / `other` / `dark` / `red_marking_like` | 702 / 439 / 1,323 / 102 / 73 |

**目視精確度**：從 `blade_like` 隨機抽 64 格，**約 41 格（64%）真的是葉片表面**，
殘餘誤判主要是灰藍色、有一點紋理的天空（紋理下限擋不掉），少數是地景與工具。
換算可用候選約 **1,200 格**，其中來自無痕跡影像的約 1,000 格。

兩條不可退化的約定：

1. **全部 `unreviewed`。** 兩位標註者都沒框 ≠ 確認乾淨——他們只框自己要框的。升成 `healthy` 要人看過。
2. **`bg_guess` 不是標籤，是排序。** 它只是讓人先看最可能是葉片的格子，不能拿它當 healthy 的依據。

另一個要記的事：這些候選**與缺陷影像同源**（同一支葉片、同一次飛行）。依 §6 第 1 條「按葉片切」，
它們必須跟原影像分在同一側，否則健康樣本會洩漏到測試集。語料沒有葉片編號（B0 報告 §5.2），
只能用檔名相鄰或時間戳粗分——這件事在 B1 要先解。

## 6. 對規格與分類表的回饋

1. **§6 加一條：帶標註／前處理痕跡的影像單獨切子集報數字。** 理由見 §3.3。
2. **§6 第 4 條在這份語料上做不到，要另外拍健康照。** 拍攝清單就是分類表 §2 的 12 項，
   優先補這份語料沒有的三種：避雷接點、VG 板／鋸齒尾緣、排水孔。B0 報告 §3 已證明開放網路湊不出來。
3. **分類表 `dataset_class_map` 已更新**：`crack` 的說明改成全語料數字，並新增 `normal_structure_survey` 區塊。
4. **`scale.method = reference_object` 有實例了**：11/192 張有比例尺入鏡。B1 可以先用這些量 cm/px，
   不必等 XMP。

## 7. 誠實的邊界

- **單一標註者、未複核。** 三份標記檔與所有數字都是。§5 的 654 就是一個判錯後修正的例子——
  其他沒重看的很可能還有。
- **Pass 1 判的是取景不是內容**：`P` 只說「葉片占畫面夠大」，不說「這張能用來訓什麼」。
- **Pass 2 的解析度看不到小東西**：避雷接點在 460 px 的格子裡可能就是幾個像素。「0 張」是「印樣上沒看到」，
  全解析度普查會不會找到幾張，不確定；但即使找到，也不會多到能撐一個類別。
- **Pass 3 的候選只是候選**：精確度 64% 是 64 格抽樣的目視數字。
- **沒有跑任何模型。**
