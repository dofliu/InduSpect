# Mode B 取像閘門（§1.2）程式化：實測報告（A3，2026-09-16）

`BLADE_CLOSEUP_SPEC.md` §1.2 寫「這條規則可以用一個分割模型或簡單的前景占比自動判」。
這份報告把那句話做出來、量出來，結論分三段：**前景占比判不出來**、**Mode A 放行是唯一可靠的硬規則**、
**外觀探針能判 P／W 但判不了 T，而且 T 的標記本身有問題**。

程式：`blade_proto/intake.py`（幾何）、`scripts/closeup_intake_gate.py`（探針 + 合併 + 統計）。
逐張結果：[`data/closeup_intake_gate_wtb.json`](data/closeup_intake_gate_wtb.json)（已進版控，`report` 子命令不需要語料）。
守門：`tests/test_closeup_intake_gate.py`。

## 0. 三個結論

1. **「簡單的前景占比」在這份語料上判不出 §1.2。** Mode A 的分割用局部天空模型，假設「背景是平滑的天空」；
   近身照的背景正是葉片本身，於是填滿畫面的葉片被當成背景。合格照（P）的分割前景占比中位數
   **比整機照（W）還低**（§2 表），任何單一門檻的平衡準確率都在 0.5–0.7 之間。這不是門檻沒調好，
   是工具的假設與輸入相反。
2. **唯一可靠的幾何硬規則是「Mode A 放行 = 整機照 = Mode B 拒收」。** 全語料 10 張被 Mode A 放行，
   其中真值 W 2 張、P **8** 張、T 0 張。P 的那幾張是 Mode A 閘門在近身照上的誤放行，逐張記進結果檔當回歸案例。
   它只抓得到 W 的一小部分（Mode A 對整機照本來就只放行約四分之一），其餘由外觀探針補。
3. **外觀探針**（凍結 ResNet18 特徵 + B2 同一個 numpy 邏輯迴歸，一對多 P／W／T、群感知 5 折、argmax）：
   P recall 0.992（832/839）、W recall 0.946（175/185）、**T recall 只有 0.195（8/41）**（41 張），P 對非 P 平衡準確率 **0.910**。
   它學的是 1,065 張**單一標註者**的取景碼，輸出「像不像近身照」加一個拒收理由，**量不到弦向占比 1/3**——
   所以是建議性判定，不是量測。

## 1. 為什麼要兩層

§1.2 的拒收條件有兩種：「整機入鏡」與「葉片太細」。前者 Mode A 本來就會辨認（那是它的輸入），
而且辨認對了時沒有歧義——一張照片不可能同時是可用的整機照與近身照。所以第一層直接重用 Mode A
的三步（分割 → 結構定位 → 拍攝閘門），放行就硬拒收，不看分數。

第二層才是學來的。它的定位是**告訴使用者為什麼不收**（W：輪轂／塔架入鏡，去走 Mode A；T：葉片太細，
靠近到弦向 ≥ 1/3），這正是 §9 第 5 條「拒收要說明原因」要的東西。

## 2. 前景占比為什麼不行

Mode A 分割（局部天空模型、1024 px 工作尺度）的前景占比，10／50／90 百分位：

| 真值 | n | p10 | p50 | p90 |
|---|---:|---:|---:|---:|
| P 近身合格 | 839 | 0.004 | **0.018** | 0.041 |
| W 整機 | 185 | 0.020 | **0.047** | 0.068 |
| T 太細／非葉片 | 41 | 0.005 | 0.019 | 0.062 |

P 的中位數比 W 低。用同一個量在 151 張分層抽樣上試四種分割模式（`local`／`rows`／`top_bottom`
的面積與距離變換最大寬度）與輪轂半徑，最好的單一門檻平衡準確率 0.73（`local` 面積、W 方向反的）。
規格那句「簡單的前景占比」要成立，得先有一個以葉片為前景的分割器，而那正是 Mode B 還沒有的東西。

## 3. 數字

群感知 5 折（`closeup_blade_groups_wtb.json` 的 `folds`），每張在自己那一折當測試；N 2 張併入 T。

| 真值 | n | 最終判定 P | W | T | recall |
|---|---:|---:|---:|---:|---:|
| P | 839 | **832** | 4 | 3 | 0.992 |
| W | 185 | 9 | **175** | 1 | 0.946 |
| T | 41 | 30 | 3 | **8** | 0.195 |

- P 對非 P 平衡準確率 **0.910**；誤放行（非 P 判成 P）39 張，其中 30 張是 T；誤拒收（P 判成非 P）7 張。
- **Mode A 放行 10 張**：正視（三片 + 塔架）2 張，真值都是 W → 硬拒收；**側視規則放行 8 張，真值全是 P**
  （95、346、634、720、968、996、1006、1064）——填滿畫面的葉片被裂縫或接縫切成上下兩段垂直伸長元件，
  「塔架」是葉片自己。第一版把全部放行都當硬拒收，P recall 掉到 0.982、平衡準確率掉到 0.905，
  等於用一條為別的取像條件寫的規則在近身照上製造誤拒收；改成只認正視放行後回到上表。
  這 8 張是 `quality.detect_side_view` 在真實影像上第一批失效案例，記進 `BLADE_INSPECTION_SPEC.md` §13 第 13 項待決策。
- Mode A 在 8 張上丟例外（遮罩全空）→ 一律收成「不放行」，不影響判定。
- 探針判錯的 P（7 張）與 W（10 張）機率都不極端；判錯的 T 則不是——30 張裡中位 p(P) = 0.88，最高 0.9997，
  調門檻救不回來，見 §4。

與 B2／線性探針的關係：分類器、標準化、折**完全相同**（`closeup_baseline.fit_logreg`／`standardise`），
只換了標籤（取景碼）與決策（argmax 取代 0.5 門檻，取景碼互斥）。

## 4. T 類的問題不全在探針

30 張被探針判成 P 的 T，逐張看過印樣：其中一半以上葉片弦向明顯超過畫面 1/3（例如 41、47、80、139、156、209、237、345 是
從葉根往葉尖看的近距離俯拍，葉片占了半個畫面），依 §1.2 的字面應該是 P；另一部分（72、120、162）是弦向約 1/5、
以天空為背景的展向遠視，才是 T 該指的東西。探針判對的 8 張 T 全是「藍天上一條細白線」，沒有歧義。

也就是說 `closeup_intake_wtb.json` 的 T 碼**混了兩種東西**：真的太細，和「近距離但拍到葉根／葉尖所以看起來像一條」。
這份標記是單一標註者在 300 px 印樣上做的（`CLOSEUP_HEALTHY_SET.md` §2 就這樣寫），閘門把不一致的那些點了出來。
**這裡不改標記**——改了就是模型替人簽核，違反第一遍標記的三條約定；結果檔的 `false_accept` 清單就是複核佇列。
T 的 recall 因此**不設測試地板**：湊數字的兩條路（調門檻、改標記）都不該走。

## 5. 對規格與流程的意義

- §1.2 「或簡單的前景占比」那半句在現有工具下不成立，規格已加註（§1.2 引用本報告）。
- Mode B 的評估域（`closeup_eval.py --domain intake_P`）仍用**人工標記**的 839 張，不換成閘門輸出：
  閘門是建議性的，評估域要固定。閘門的角色是在 App 端拒收並說理由。
- App 端尚未接：Mode B 演算法本身還沒有實作，閘門先在原型端釘住行為與數字；接上時第一層可直接呼叫
  既有 `blade_capture_gate.dart` 的整條鏈（Dart 端本來就有），第二層需要裝置端跑一個 ResNet18 特徵抽取
  （或改用 Tier 1b 的本機 VLM 判取景）。

## 6. 重現

```bash
cd blade_prototype
python scripts/closeup_intake_gate.py run --dataset <語料根目錄> --out data/closeup_intake_gate_wtb.json   # 約 30 分鐘（幾何那層）
python scripts/closeup_intake_gate.py run --out /tmp/probe_only.json                                     # 沒有語料：只跑探針
python scripts/closeup_intake_gate.py report                                                             # 讀進版控的結果
pytest tests/test_closeup_intake_gate.py
```

特徵檔 `data/closeup_features_resnet18_wtb.npz` 由 `scripts/closeup_features_cnn.py` 產生（唯一 import torch 的檔案）；
探針與 `report` 都不需要 torch。
